The HTTP code lives in the `:core:api` module, `core/api/src/main/java/com/github/e0ipso/tokkl/api/`.

`TokklApi` is the app's whole API contract, the requests that section 6 of Tokkl's `docs/PRD.md` lists and the app sends. It groups one suspend method per request by resource: `account` (`/me`, `/me/preferences`, `/workspaces/{id}`), `entries`, `trash`, `projects` (with their tasks), `clients`, `tags`, `reports` and `timer`, each its own class in a file named after it (`AccountApi.kt` and so on). Each method fixes its request's method, path, query, body and whether OkHttp may send it twice, and takes typed values: core:model's typed ids (`WorkspaceId`, `EntryId`, `ProjectId`, `ClientId`, `TaskId`, `TagId`), `Instant`s and `LocalDate`s, and request bodies, so core:api depends on core:model and exposes it. Bodies with a fixed shape are `@Serializable` data classes encoded with `ApiJson`, which leaves out a property that has a default and still holds it, and writes every other one, null included. That is how `TimedEntryBody` sends `"stop":null` for a running entry and leaves `created_with` out of an update. The report bodies are written field by field in `ReportsApi.kt`, because the filter fields (`ReportFilter`) sit at a place that differs by report. Each method also fixes the type its answer reads as, and core:api declares those types; no caller passes a deserializer. `GET /me` has two methods: `account.me()` reads the whole `Me` that sign-in needs, and `account.defaultWorkspace()` reads `MeWorkspace`, the default workspace and role alone, for the catalog pages and the reports. `trash.list()` reads `TrashEntry` rows, whose `id` is an `EntryId`, and `trash.probe()` reads the same route as a bare `JsonArray` for the capability probe. `savePreferences(change)` answers with the stored preferences as a `JsonObject`. `WorkspaceItems.kt` holds the catalog answers (`MeWorkspace`, `WorkspaceSettings`, `WorkspaceClient`, `ProjectClient`, `WorkspaceProject`, `ProjectTask`, `WorkspaceTag`, `PurgedEntries`) and `ReportsApi.kt` the report rows (`ReportSearchRow`, `ReportSearchEntry`, `WeeklyReportRow`). Each feature's server class, such as `TagsServer`, `ProjectsServer`, `ReportsServer` or `TrashServer`, maps those answers to core:model or page types. `TokklApi` builds the groups over one `TogglApiClient`. `ApiClientProvider` and `Session.api()`, both suspend, hand out `TokklApi`, and nothing outside `:core:api` builds a URL or a JSON body or calls `TogglApiClient`; only `Session` and sign-in construct one, to wrap it. To add a request, add a method to its group's class, and its exact bytes to `TokklApiTest`, which pins method, path with query, and body for every method. `SharedHttpClient` is a class that Koin makes once, and its `instance` is the app's only `OkHttpClient`, so its connection pool, dispatcher and security settings apply to every request. It builds the client on first use, which loads the platform's CAs, so that happens off the main thread. `cancelAll()` cancels every call in flight for sign-out, and `dropIdleConnections()` empties the pool when MainActivity sees the network drop. New security settings, such as the trust manager for a pinned self-signed certificate, go into its `build()`, never into a second client. `SingleHttpClientTest` reads the constant pool of every compiled app class, in every module, through `ClassReferences`, the class-file reader in `app/src/test` that `NoDeviceZoneTest` shares, and fails when any class but `SharedHttpClient` builds an HTTP client, so an import alias or a fully qualified name cannot hide one.

`ConfiguredServerGuard`, an interceptor on that client, throws `HostNotAllowedException` for any request whose scheme, host or port differs from the `ConfiguredServer`'s `current`. `ConfiguredServer` is a Koin single too. It reads the stored server through `StoredServer`, which `ServerConfigStore` implements, on every request, so every process sends only to the stored server from its first request on; nothing has to set it at start. It does so before OkHttp connects, so no credentials leave the phone, and `TogglApiClient` returns it as `ApiError.HostNotAllowed(origin)` with the origin as `scheme://host:port`. `current` is the stored server, or the URL being tried inside `signingIn`, which holds a `Mutex` so one sign-in runs at a time. With neither, every request is refused. The guard also refuses a plain `http://` server the user has not confirmed, and the trust manager refuses a self-signed certificate the user has not pinned (see the connection trust node). OkHttp's own redirects are off (`followRedirects(false)`, `followSslRedirects(false)`). The guard follows a redirect itself, and only to the same origin.

`ServerUrl.parse` accepts an http or https base URL that may carry a path, such as `https://example.com/tokkl`, and builds endpoints under `<base>/api/v9` and `<base>/reports/api/v3`. It refuses a URL with a user name or password, so the stored URL never holds a secret. It keeps only the scheme, host, port and path, so a query or fragment, as in a URL copied from the browser's address bar, is dropped, and so are empty path segments: `https://example.com/tokkl/` and `https://example.com/tokkl` are the same server. `ApiCredentials` builds the Basic header from `<api_token>:api_token` or `<email>:<password>`. Tokkl splits the decoded header at the first colon, so a password may contain colons and an email may not.

`TogglApiClient`'s calls, and so every `TokklApi` method, suspend. Each switches to the client's IO dispatcher and runs `Call.execute` there through `executeCancellable` (`CancellableCall.kt`), which cancels the OkHttp call when the coroutine is cancelled, so a page that goes stops its reads at once. The call runs on that thread, not on OkHttp's dispatcher, so the dispatcher's limit of five calls per host never queues a request behind the timer event stream, and the exceptions that tell whether a request left the phone stay those of `execute`. A cancelled call throws the cancellation instead of returning an `ApiResult`. The catalog pages and the trash send each change through core:session's `ServerChanges`, which runs it in the application scope and starts the cache refresh once the server accepts it, so the change and its refresh land when the page goes meanwhile; the page awaits the answer and shows it while it is still there. Other writes the user sent from a screen (the timer templates, sign-in, the timer actions and Undo) run in `NonCancellable`, so they land and their answer is recorded when the screen goes meanwhile, as they did when the calls blocked. The queue, the refresh and the preference sends run in the application scope, which nothing cancels. `ApiCallCancellation` stays for the CSV export and the event stream, which an account change or the stream's silence cancels from outside.

`TogglApiClient.get` and `send` decode a 2xx body with a kotlinx.serialization deserializer, and an empty body fails to decode. Calls that expect no content use `sendNoContent`, which treats any 2xx as success and ignores the body. Tokkl's DELETE routes for time entries, tasks, clients and tags answer 200 with an empty body, while the project DELETE answers 200 with the project id as JSON (`../tokkl/packages/api/src/routes/togglV9.ts`). `sendNoContent` handles both.

When a connection OkHttp reused fails after the request went out, OkHttp sends the request again on a new connection, so a POST whose answer was lost can create its object twice. `send(..., resend = false)` sends through `SharedHttpClient.sendingOnce`, a client derived with `retryOnConnectionFailure(false)` that shares the pool, interceptors and trust checks, and the caller gets the failure instead. `TokklApi` sends that way every time-entry write (create, update, stop and delete), the restore of a queued short Stop, and every catalog create.

`sendRefusable` serves the timer actions, which answer a refusal with a 409 whose body has the same type as their 2xx answer, the timer state. It sends once (`resend = false`) and returns `Refusable(value, refused)`: `refused` is true for a 409 body that decodes. A 409 whose body is a JSON string becomes `ApiError.UnexpectedStatus` with that reason. A request tagged `StreamingRead` reads its body with no read timeout, for the timer event stream; `StreamingReads` lifts that one timeout and nothing else.

The connection pool keeps an idle connection for 4 seconds (`IDLE_CONNECTION_SECONDS`), not OkHttp's default 5 minutes. Tokkl runs on Node, which closes a keep-alive connection after 5 idle seconds, and OkHttp reuses a connection idle for under 10 seconds without checking it. A request sent once on such a closed connection failed, so a timer action a few seconds after the last request said there was no connection. With a 4 second pool the client drops the connection before the server does and opens a new one. `SharedHttpClient.sendingOnce`, in its companion, derives a client that does not retry; it shares the pool, interceptors and trust checks.

Unit tests build the client through `TestApi` in core:api's test fixtures: a `SharedHttpClient` over a `ConfiguredServer` and `ServerTrust` the test sets and changes, so no test leaves a server or trust behind. `api()` gives the app's `TokklApi` and `client()` the bare transport, for a test that sends a request the app does not. Its clients run on the calling thread (`Dispatchers.Unconfined`) by default, as the tests' unconfined scopes expect. Device tests take the app's own client from Koin through `appHttp` and `appApiClient`, wrap one with `tokklApi()` to pass it to the app's code, and read the signed-in session's transport with the `Session.client()` extension in `AppSession.kt`.

Every call returns `ApiResult.Success` or `ApiResult.Failure(ApiError)`. `ApiResult.kt` has `map`, `flatMap` for the next call, `fold`, `getOrElse`, `onSuccess` and `onFailure`, so a caller passes a failure on with `getOrElse { return it }` instead of a `when`, and `ApiResultTest` pins them. 403 maps to `AuthFailed`, 429 to `RateLimited` with the `Retry-After` seconds (null when the header is missing or not a whole number), and any other status outside 2xx to `UnexpectedStatus(status, message)`. `message` is the server's reason when the body is a JSON string, as Tokkl sends for a change it refuses, such as "Name has already been taken". The catalog pages show that reason for a 4xx. `Network` wraps the `IOException` of a request that got no response. `InvalidResponse` is a 2xx body that is not the expected JSON. `TrustRefused` covers the `TrustQuestion`s `CleartextNotConfirmed` and `UntrustedCertificate`, and `CertificateHostMismatch`. The client also reports each to its `TrustListener`.
