Every signed-in screen sits in `SignedInFrame` with the bottom bar of `navhost/AppNavigation.kt` in the app on a compact window, as on Tokkl's web app on a phone (`docs/PRD.md` 5.11, B1 to B3). The bar, the rail and the More sheet show `TopLevelPages`, which `di/NavigationModule.kt` builds from the `TopLevelDestination`s each feature names in its `FeatureRoutes.pages`: the page's route, label, icon, section hue, position, whether it sits on the More sheet, and `isAvailable`, what it needs of the server's `Capabilities` (Trash the trash API, Timer templates the favorites key, Pomodoro the timer API). `TopLevelPages.unavailable` gives the pages the server lacks, which show nowhere and open Timer in their place. The pages stand in the order of their positions, which follow NAV in App.tsx in steps of ten. Each page's value, such as `tagsPage`, sits in the feature's `XEntries.kt`, not in the file of its Koin module: a top-level value declared below `module {}` in the same file is still null when the module's lambda runs, which on 2026-11-08 failed every unit test that loaded `appModules`. Opening a page from the bar or the sheet puts it right above Timer, so Back goes to Timer and Back from Timer leaves the app. A screen opened from a page, such as Licences from Settings, stacks above that page, and the bar keeps marking the page. Every signed-in page draws `TokklTopBar` with its title as its `Scaffold`'s top bar. The pages in the bar have no back arrow there. Licences, the project and client forms and the entry form pass `onBack` for one.

The app's `navhost` package names no feature, by package or R class, and `PackageLayersTest.theNavigationHostNamesNoFeature` fails when it does. Each feature hands the host its parts through core:navigation. `PageBadge` is an open class; a feature declares its own subclass, `TimerBadge` or `PomodoroBadge`, and binds it to `PageBadge` in Koin. Each puts a running dot on its page's item with the label TalkBack reads as its state: Timer's while an entry runs ("Timer running"), Pomodoro's while the server's session runs; `SignedInViewModel` turns them into the frame's `badges` (`runningPages`). A route that shows the timer says so with `Route.showsTimerNotices` (Timer, the fullscreen timer and Pomodoro), and there the short Stop's Undo and the timer's notices share one snackbar host. A focused route, the fullscreen timer, shows alone. A feature that shows something in the frame binds `FrameContributions`: `frameBand` gives the band right above the bar (or at the bottom beside the rail) and `frameNotice` a notice over the page. Only the sync feature binds one, `SyncFrameContributions`: the sync feature's `SyncStatusBand`, from `LastAnswer`, the time of the last 2xx, and its discarded changes' notice, both from `SyncFrameViewModel` in the session's store. A feature's notice sits below the timer's snackbars and the notification permission's prompt. The band's sign-in opens `SignInRoutes.again()`, which the sign-in feature binds. `navhost/SignedInViewModel`, in the signed-in session's store, gives `SignedInHost` the dots, the short Stop's Undo and the trust prompt. `TokklNavHost`, in `navhost`, takes the features' `FeatureNavigation`, the top-level pages, the sign-out count, the capabilities, the `SignInRoutes`, a function that gives the timer's `TimerFrame` and the notification permission's prompt as plain parameters, which MainActivity injects (`by inject()`) and hands over; MainActivity is where the app names the Timer feature's view model, whose `frame` it passes, and the notification feature's prompt. No composable of the host calls `koinInject` or `getKoin`. The frame reads the timer only through `TimerFrame`, in core:timerstate's `timernotice` package, which `TimerViewModel.frame`, a `TimerFrameSource`, implements: whether the timer settled idle, which closes the fullscreen timer and the entry form above it, whether the Timer page shows its List view, the starts that may ask for the notification permission, and the notices the frame shows. Its More icon and the snackbars' Undo come from core:ui, and the bar's item styling, `navhost/NavigationBarItems.kt`, is the app's. The Pomodoro page hands its starts and retries to the permission prompt through `NotificationPrompts`, which `NavigationHost` lends every screen; it stays in core:navigation because the frame and the Pomodoro feature both use it.

`ui/WindowWidth.kt`'s `windowWidth()` maps the Material 3 adaptive library's window size class to `COMPACT` (under 600dp), `MEDIUM` (from 600dp) or `EXPANDED` (from 840dp); a phone held sideways counts as expanded. Every class shows the same screens. Medium and expanded windows get `AppNavigationRail` with the same items in place of the bottom bar. On an expanded window in the Timer page's List view, the entry form opens beside the history (`showsEntryBeside`), and `SignedInPanes` keeps the Timer page and the form each in one place in the composition, so a rotation or a fold that changes the layout keeps their saved state. The Calendar view keeps the whole width, and wide content caps at `TokklSpacing.wideContentMaxWidth`, 1100dp, as the web app's `.page` does. `AdaptiveLayoutTest` forces a window with `DeviceConfigurationOverride.WindowSize`, which scales the density down when the window is larger than the device's, so those tests compare positions, not sizes.
