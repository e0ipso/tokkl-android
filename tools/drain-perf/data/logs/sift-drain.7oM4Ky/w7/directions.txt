=== .ai/sift/open/offline/feature/TKA-0027--change-queue.md
## Direction

- Keep a FIFO of pending operations in Room. The operations are create or start, stop, update and delete. Only time entries go in the queue.
- Apply each operation to the cache at once and mark it unsent. Until it is sent, keep it applied over refreshed rows so the user still sees it.
- An entry created offline gets a local ID. Once the server creates it, map the local ID to the server ID, and later operations that reference it use the server ID.
- A sender drains the queue in order. A network failure, a 5xx or a 429 stops the drain and keeps the operation queued, and a 429 waits for `Retry-After` before the next try.
- TKA-0073 owns the handling of 409, 404, 400 and 403. Until it lands, any other failure stops the drain and keeps the operation queued, so nothing is lost.
- Send full field values. The last write to reach the server wins, and nothing merges, except a queued start, which TKA-0072 checks against the running entry before sending.
- Taps never await the network. Start and stop times are the tap times.
- The notification, widget and tile read the running entry from this cache, so they change at once while the queue sends behind them.
